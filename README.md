# CS-230-The-Gaming-Room-Design-Document

The company, The Gaming Room, wanted to create a web-based version of their Android game, Draw it or Lose It. The goal was to have the application be accessible across platforms while keeping the integrity of the original Android game. The game needed to be able to support multiple teams and accommodate multiple players. There also could only be one active instance of the game existing in memory at a time. Lastly, game and team names needed to be unique to prevent duplication, and a unique identifier was required for every game, team, and player.

When developing this documentation, the best section had to be my evaluations table. I put a lot of research into this section, and it took me a while to comb through each upside and downside to the suggested OS. However, I also think that out of all the sections I completed, I would've liked to improve my evaluation table even further. While there was a lot of brief information, I could've definitely put even more thought into the table. It would've helped to expand upon the points I made in the recommendation section. Overall, working through the design document became useful while developing the application. Having the summary and requirements laid out for me in an organized paper ensured that I was meeting the client's expectations for the application.

It's important to consider the user's needs when designing any software, as ultimately, the success of the application relies on the good experience of the user. If the user is frustrated in any capacity, such as the program running slow or the user interface being difficult to navigate, then they likely won't return. While developing the software design document, I made sure to consider what would give the user the best possible experience. This heavily influenced my evaluations table and my recommendation, to which I suggested Windows as the best OS platform. Windows is the most popular system, so most players will expect Draw It or Lose It to be compatible with it. Over time, the company can branch out to Linux and Mac if they wish, but I believed that starting out with Windows would be the best business decision due to most users having a Windows-based computer. 

If I were to analyze and design a similar application, I would prioritize both the users' and the client's requirements, treating them as essential alongside standard software design considerations. This approach ensures the application meets the expectations of both the client and end-users while adhering to industry best practices in software development.
